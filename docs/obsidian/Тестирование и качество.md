# Тестирование и качество

Часть проекта [[learn-aziral]].

## Стенд

Vitest 4 + jsdom + Testing Library. Настройка — `vitest.config.ts`,
setup-файл `src/test-setup.ts` (одна строка: импорт `@testing-library/jest-dom`).
Отдельный `tsconfig.test.json` для typecheck.

Покрытие через `v8`, из подсчёта **исключены** `src/app/components/ui/**`
(сторонние примитивы), setup и сами тесты.

```bash
npm test            # vitest run
npm run test:watch
npm run test:coverage
```

## Что покрыто — 554 строки тестов

Появились в `a90ef3a`, три файла:

**`client.test.ts` (167 строк)** — самый ценный. Проверяет не эндпоинты,
а **контракт транспорта**:
- парсинг JSON на 2xx, тело POST уходит строкой;
- `credentials: include` есть в **каждом** запросе;
- заголовок `Content-Type`;
- сообщение об ошибке берётся из `data.error`, иначе `HTTP <код>`;
- не-JSON тело не роняет клиент;
- сетевой отказ пробрасывается;
- **детект бана**: событие `azr:banned` летит только на 403 с точным текстом,
  и не летит ни на обычный 403, ни на 401;
- `checkUsername()` экранирует имя в query.

**`AuthContext.test.tsx` (161 строка)** — жизненный цикл сессии:
загрузка, успех/провал `fetchMe`, снятие `loading` в обоих случаях,
реакция на `azr:banned` (в том числе когда пользователя ещё нет),
логаут (сбрасывает сразу, редиректит даже если запрос упал),
`updateUser`, и бросок ошибки при `useAuth` вне провайдера.

**`validation.test.ts` (226 строк)** — правила из `src/utils/validation.ts`.

## Правила валидации

```
PASSWORD_MIN_LENGTH = 8
SPECIAL_CHAR_REGEX  = /[!@#$%^&*(),.?":{}|<>\-_+=[\]\\/]/
EMAIL_REGEX         = /\S+@\S+\.\S+/
```

Валидаторы: `validateEmail`, `validatePassword`, `validateName`,
`validateRequired`, плюс составные `validateContactForm` и `validateRegisterForm`
(последний проверяет совпадение паролей).

В шапке файла заявлено: *«единый источник правды — те же правила на фронте
и в бэкенде»*. Синхронность **ничем не проверяется автоматически** — если
правило поменяется на сервере, тесты здесь этого не заметят.

> [!warning] Слепая зона
> Страницы (9 файлов, ~7 000 строк) не покрыты вообще. Непокрытыми остаются
> самые хрупкие места: парсеры импорта в `TestBuilderPage` (`parseQuickText`,
> `parseSpreadsheet`) и логика проверки ответов в `TestTakingPage`.
> Это первое, что стоит покрыть — там чистые функции, тестировать легко.
